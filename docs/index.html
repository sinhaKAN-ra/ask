Commands for bash and zsh.

WEB SEARCH PROVIDER
Two keys, two jobs.

Your model key generates answers. A search key retrieves web results. This enables web search, not browser automation.

1

Install the command

Python 3.8+ and pipx are required. Already installed? Use pipx upgrade aolbeam-ask.

pipx install aolbeam-ask
pipx ensurepath

Reopen your terminal if ask isn’t found.

Other install options & latest source

Run once with uvx aolbeam-ask "hello", or install with python -m pip install aolbeam-ask. The package name is aolbeam-ask; the command is ask.

The setup and diagnostic flags below require the updated CLI. Until a new package release is published, install from an updated checkout:

git clone https://github.com/sinhaKAN-ra/ask.git
cd ask
pipx install --force .

If --setup-search is unrecognized, use the manual config option in step 3.

2

Connect your AI model

Create a key at Groq’s console ↗. Replace the placeholder below with your own key.

export GROQ_API_KEY="YOUR_GROQ_KEY"

Using another model? Set base_url, model, and api_key_env in ~/.ask-cli/config.json.

3

Give ask access to Brave Search

Create a Brave Search API account, choose a plan, and create a key in your API dashboard ↗.

export BRAVE_API_KEY="YOUR_BRAVE_KEY"
ask --setup-search brave

A Brave browser installation does not provide an API key. Check the provider’s current pricing and request limits.

Keep keys across terminal sessions

Add the export lines to ~/.zshrc (zsh) or ~/.bashrc (bash), then open a new terminal. Treat that file as private: it contains your keys. Never commit keys to your project.

Manual config / older CLI versions

Run ask --config once to create the config. Merge these settings into ~/.ask-cli/config.json (%USERPROFILE%\.ask-cli\config.json on Windows), keeping your model settings:

{
  "search_provider": "brave",
  "search_api_key": "",
  "search_api_key_env": "BRAVE_API_KEY",
  "web_fallback": true
}

Set the environment variable above, then run ask -w "latest Python release; cite sources". Older versions may display saved keys in --config; keep that output private.

4

Check it. Then ask something.

Check local configuration, test a real search, and get your first sourced answer.

ask --doctor
ask --doctor --check-web
ask -w "What changed in the latest Python release? Cite sources."
✓

What success looks like
Doctor reports a live search result count from brave. Your answer includes numbered source URLs.

The local check verifies key presence. The live check sends a test query and may consume search credits. Your question also uses your model provider.

A FEW GOOD QUESTIONS

Before you ask.

Do I need both API keys?

You need a model provider key for hosted models. DuckDuckGo search needs no additional key; Brave, Tavily, and Serper each need their own search key. Local Ollama can use a placeholder model key.

Does ask control my browser or edit my files?

No. It reads files you attach, accepts piped input, calls your chosen model, and retrieves search results when enabled. It prints suggestions; it does not execute generated commands or edit your code.

Where does my data go?

Questions, attached content, and recent conversation history go to your model provider. Web searches send the question to your search provider. Sessions are saved locally under ~/.ask-cli/sessions. Use --no-history to skip reading and saving sessions; this still calls your configured providers.

Why doesn’t my search key work?

Check that you selected the matching provider and set the variable in the same terminal. Use ask --doctor, then ask --doctor --check-web. An HTTP 401 or 403 suggests a key or plan issue; 429 indicates a rate or quota limit. Check the provider dashboard.

Is web search always accurate?

No. The model’s self-check can miss a need for fresh information, and retrieved sources can be incomplete. Use -w when freshness matters and open the cited sources to verify important claims. Forced search fails visibly when no usable results are available.
